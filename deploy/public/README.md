# Публикация food-consumption

Основной вход:
- `https://food-consumption.solovyshka.com/app/` — первая установка;
- `https://food-consumption.solovyshka.com/app/version.json` — версия для обновления;
- `https://food-consumption.solovyshka.com/api/mobile/` — защищённый API.

Резервный вход:
- `https://vladislavsolovei.ru/food-consumption/app/`;
- `https://vladislavsolovei.ru/food-consumption/api/mobile/`.

DNS Cloudflare: A `food-consumption` → `51.254.219.211`, DNS only.
Также A `*` → `51.254.219.211`, DNS only: новые поддомены без собственных
записей направляются на OVH. Конкретные записи имеют приоритет.
Это настройка DNS; для каждого нового приложения всё равно нужно создать
маршрут nginx, выпустить HTTPS-сертификат и настроить его серверную часть.
Для этой схемы API-токен Cloudflare не требуется.

На коробке:
- API `food-mobile-api`, `192.168.100.41:8092`, PostgreSQL остаётся на коробке;
- `reverse-ovh-food` → OVH `127.0.0.1:18092`;
- `reverse-rf-food` → русский сервер `127.0.0.1:18092`.

Туннели доступны только на loopback публичных серверов. Внешний доступ идёт
через HTTPS nginx, API требует токен. Токен и код подключения не публикуются
на странице, в version.json или APK.

OVH использует существующий SNI-переключатель :443: домен питания добавлен
к HTTPS на 127.0.0.1:8443. Маршруты аудиогида и Telegram сохранены.
`enable-https.py` проверяет nginx и сохраняет резервную копию перед изменением;
certbot автоматически продлевает сертификат и перезагружает nginx.

## Выпуск обновления

1. Обновить `version` в `mobile/pubspec.yaml`: и имя версии, и число после `+`.
2. Передать исходники на коробку в `/home/solovyshka/builds/food_checking/`.
3. На коробке выполнить:

```sh
cd /home/solovyshka/builds/food_checking
python3 deploy/build-apk.py
```

Скрипт проверяет интерфейс и загрузчик, собирает release APK, проверяет подпись,
создаёт version.json и публикует одинаковый файл на обоих серверах.
Подпись хранится в `/home/solovyshka/.config/food_checking/`; менять этот ключ нельзя.
`--skip-build` публикует уже собранный APK, `--skip-publish` оставляет файл на коробке.

Публикация атомарная: каждое обновление лежит в отдельной папке
`/var/www/food-consumption-releases/<versionCode>-<sha256-prefix>/`,
а `/var/www/food-consumption-app` указывает на текущую версию.
Старые файлы остаются доступны, чтобы докачка не смешивала разные APK.

Приложение проверяет `/app/version.json` при запуске и кнопкой в верхней панели.
При появлении новой версии показывает «Скачать · RU» и «Скачать · OVH».
Загрузка идёт частями с докачкой и резервным входом. Перед установкой проверяются
SHA-256, имя пакета, номер версии и совпадение подписи с установленным приложением.
Затем открывается стандартный установщик Android. При первом обновлении Android
попросит разрешить установку для приложения «Еда».
