# Еда — Android-дневник питания

Версия 1.0.4+5, Android 8.0 и новее. [Установка и обновление](https://food-consumption.solovyshka.com/app/).
Резервный вход: https://vladislavsolovei.ru/food-consumption/app/.

Можно написать или продиктовать, что съедено, добавить фотографию, сохранить запись
в очередь либо сразу нажать «Разобрать и рассчитать». Голос распознаётся на коробке
через GigaAM с резервным Whisper. Текст после распознавания можно исправить.
Кнопка «Разобрать очередь» передаёт до 30 записей в один запуск существующего Grok Bot.

Результат сохраняется автоматически, даже если телефон закрыт. В дневнике две таблицы:
«Что съедено» — название, исходное количество и единица; «Калорийность» — порция
в граммах/миллилитрах, ккал на 100, итог и источник значения. Например, «два яйца»
остаётся двумя штуками, а масса для расчёта отображается отдельно с отметкой оценки.
Даты и приёмы пищи сохраняются за каждой исходной записью.

Типовые значения и расчёты по фотографии — оценки. Жирность молока сама по себе
не задаёт точную калорийность конкретной марки. Подтверждённые значения с этикетки
повторно используются для совпадающего названия и единицы. Неизвестная масса или
калорийность остаётся пустой и не входит в итог; дневник показывает число таких позиций.
Продукты можно добавить вручную, исправить после разбора или удалить.

Фото выбирается системным диалогом без общего доступа к галерее. Создаётся уменьшенная
JPEG-копия до 1600 пикселей без EXIF, исходник не меняется. Черновик хранится на телефоне;
при отправке фото сохраняется в PostgreSQL на коробке. Для Grok создаётся временная копия фото на OVH: случайная HTTPS-ссылка под основным
доменом, без входа и списка изображений, доступна 2 часа. После срока она не открывается;
файлы удаляются таймером каждую минуту. Исходное фото остаётся в очереди на коробке для
повторного разбора. Для исходных текстов и возврата результата выдаётся доступ только
к выбранной задаче на один час. Общий токен приложения Grok не получает.
После подтверждённого сохранения записи копия из черновика телефона удаляется.

Очередь, запрос разбора и результат защищены от повторов. UUID и неизменяемые данные
отправки сохраняются в черновике до запроса к серверу. Потеря ответа вебхука не запускает
вторую задачу автоматически. После часа без результата исходные записи освобождаются
для повторного разбора. Ошибки модели возвращают записи в очередь.

## Сервер и Grok

Сервис `food-mobile-api`, PostgreSQL на коробке. Новая миграция
`0007_grok_food_analysis` добавляет фотографии, задачи разбора и отдельные таблицы
`mobile_parsed_foods` / `mobile_parsed_nutrition`. Старые записи остаются в
`consumption_entries`. Исходные тексты находятся в `consumption_transcripts`.

Текущий разбор использует существующий вебхук Grok Bot, а не xAI API.
Ключи `GROK_BOT_WEBHOOK_URL` и `GROK_BOT_WEBHOOK_KEY` находятся в закрытом
серверном окружении. Прокси: `GROK_BOT_PROXY_URL` (по умолчанию `http://127.0.0.1:10809`).
`FOOD_GROK_CALLBACK_BASE_URL` задаёт публичный HTTPS-вход (по умолчанию основной домен).
Короткий вебхук передаёт адреса задачи; подробная инструкция и схема результата
читаются отдельным GET, чтобы Grok не обрезал тело запроса. Инструкция находится
в `app/services/grok_analysis.py`. Старый `/preview` оставлен для совместимости.

API: `POST /images`, `POST/GET /queue`, `DELETE /queue/{id}`, `POST /queue/parse`,
`GET /queue/jobs/{uuid}`, `GET /diary`, `PATCH/DELETE /grok/foods/{id}`;
префикс `/api/mobile`. Запуск не равен завершению: приложение проверяет статус задачи.
Grok получает отдельные `input_url`, `result_url` и авторизацию одной задачи.
Результат проверяется по схеме, сохраняется транзакцией, итоги считаются на сервере.
Возврат того же результата повторно не добавляет строки и не перезаписывает ручные правки.

Настройки и черновик телефона зашифрованы Android Keystore, резервное копирование
отключено. Подключение требует персональный код; публичные входы работают через HTTPS.

## Сборка на коробке

Исходники: `/home/solovyshka/builds/food_checking/mobile`.
Flutter: `/home/solovyshka/develop/flutter/bin/flutter`.
Постоянный ключ: `/home/solovyshka/.config/food_checking/android-release.jks`,
параметры — `android-release.properties` там же; `android/key.properties` ссылается на них.
Секреты не входят в репозиторий. Этот ключ необходим для обновления установленного APK.

```sh
cd /home/solovyshka/builds/food_checking
python3 deploy/build-apk.py --skip-publish
# После проверок опубликовать уже собранный файл:
python3 deploy/build-apk.py --skip-build
```

Скрипт проверяет приложение, собирает подписанный APK и выпускает одинаковую версию
на обоих публичных входах. Обновление внутри приложения поддерживает докачку,
проверку размера, SHA-256, пакета и подписи. Микрофон и установку обновления
нужно дополнительно проверить на физическом Android-телефоне.

[Инфраструктура публикации](../deploy/public/README.md).
